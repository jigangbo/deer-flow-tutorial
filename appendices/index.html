    run 对 thread 的一次执行（agent loop 调用）；run 历史的状态过滤是"发生态"不是任务态 第 6、12 章

    App（Gateway） 未发布的应用层 backend/app/：FastAPI Gateway + IM 渠道 第 0、14 章
    lead agent 由 make_lead_agent() 组装的主 agent，LangGraph Server 图工厂入口 第 6、9 章
    subagent 由 SubagentExecutor 后台委派的子代理；execution_id ↔ tool_call_id 关联链贯穿 ToolMessage/SSE/持久化 第 9 章
    sandbox 沙箱执行抽象：LocalSandboxProvider（开发）与 AioSandboxProvider（Docker 生产隔离） 第 8 章
    skill SKILL.md frontmatter + 资源目录的领域技能；public/custom/集成三来源 第 7 章
    extension 通过贡献点（middleware/observer/service/router）装进平台的打包扩展 第 16 章
    MCP Model Context Protocol：外部工具接入协议，每 server 独立进程 第 15 章
    artifact agent 产出的文件/代码产物，经 present_files 呈现、前端面板预览 第 2、7、18 章
    lease 租约：带心跳续期的认领凭据，覆盖 run 所有权、调度认领、渠道 leader、MCP 任务 第 12、20 章
    SSE Server-Sent Events：run 流的传输形态（messages-tuple + 有界 values + 自定义事件） 第 6 章
    stream bridge Gateway worker 与 SSE 客户端之间的事件桥（memory 单进程 / redis 多进程） 第 20 章
    middleware 模型调用前依次执行的中间件链（ThreadData → Uploads → Sandbox → Summarization → …） 第 6 章
    provisioner 8002 端口的可选服务，K8s 沙箱模式下供给容器与 PVC 第 8、20 章
    DEER_FLOW_HOME 运行时主目录（默认 backend/.deer-flow/），存线程数据、数据库、secrets 第 6 章
    Blockbuster 检测异步上下文中阻塞 IO 的运行时工具；tests/blocking_io/ 的严格门禁 第 19 章
    Alembic 后端 schema 迁移工具；Gateway 启动自动 upgrade head 第 20 章
    run-context 信任边界 non_interactive 等服务端键只认内部认证调用方，客户端副本一律剥离 第 12、20 章
    trace id 请求级关联 ID（X-Trace-Id），ContextVar 为唯一来源，派生载体只写不读 第 19 章
    TanStack Query 前端服务端状态管理器；线程状态归一化后的归属地 第 18 章

    附录 E 常见问题 FAQ¶

    Q1：端口冲突——2026/3000/8001 被占用怎么办？ 先 make stop（本地栈）或 make down（生产栈）释放。Docker 入口端口由根 PORT 环境变量控制（仅影响 Compose 发布端口）；本地 Next.js 固定 3000、Gateway 固定 8001，.env 改动不会影响 make dev 的端口等待（根 AGENTS.md）。注意 Windows 上 0.0.0.0 绑定可能撞 Hyper-V/winnat 保留段（见 Q6）。

    Q2：模型 API Key 报错如何排查？ 确认 config.yaml → models: 段对应供应商的 api_key 已填、供应商未 disable；跑 make doctor，它专门检查 LLM provider 连通性（scripts/doctor.py:3-8）。密钥类环境变量看 .env.example。模型能力位（supports_vision、深度思考、context_window）错配的症状是功能静默降级而非报错（config.example.yaml:132-143）。

    Q3：沙箱启动失败？ 三步：确认 Docker daemon 在跑；make setup-sandbox 预拉镜像（Makefile:151-152）；确认 config.yaml → sandbox: 选择的 provider 与运行形态匹配（local 直执行仅开发用，Docker 生产用 AioSandboxProvider，K8s 模式才需要 8002 Provisioner）。Compose 默认不挂 Docker socket，DooD 沙箱要显式加 overlay（docker/docker-compose.yaml:161-166）。

    Q4：pnpm 版本不对 / Corepack 不生效？ 仓库锁定 pnpm@10.26.2（frontend/package.json:133），要求 Node 22+。host 调用统一走 scripts/pnpm.py：native Windows 先试 pnpm.cmd、POSIX 先试 pnpm，Corepack 回退按同序尝试 corepack.cmd/corepack，并从 frontend/ 目录运行以对齐锁定的包管理器版本（根 AGENTS.md）。

    Q5：改了配置不生效？ 分三类：① 经 Gateway API 改的两份配置立即生效；② 直接改 config.yaml，make dev 的 uvicorn 监听 *.yaml 会自动重启（backend/Makefile:12-13）；③ restart-required 字段（scheduler poller 字段、run_ownership、agent_storage、logging.enhance、stream_bridge、checkpoint_channel_mode）必须重启 Gateway，且多实例下所有 Pod 一起重启（CONFIGURATION.md:777-781）。scheduler.recursion_limit 例外：分发时读取，下次 run 生效（backend/AGENTS.md:14）。

    Q6：Windows 特有问题合集？ ① 前端 dev server 绑定 127.0.0.1 避开 Hyper-V/winnat EACCES（#2870，frontend/AGENTS.md:34）；② root Makefile 在 Windows 用 cmd.exe 执行并借 scripts/run-with-git-bash.cmd 跑 shell 脚本（Makefile:9-13），所以需要安装 Git Bash；③ 后端进程统一注入 PYTHONIOENCODING=utf-8 PYTHONUTF8=1 防控制台乱码（backend/Makefile:33-36）；④ POSIX-only 的 live 测试用 os.name 守护收集（backend/AGENTS.md:226-227）；⑤ 技能文本一律显式 UTF-8（读 utf-8-sig、写 utf-8），别依赖系统 locale。

    Q7：非本机访问 dev server 登录页 403？ Next 的 allowedDevOrigins 会挡住未声明来源的 /_next/*、字体与 HMR 请求，症状是 403 且页面无法交互（含登录）。设置 DEER_FLOW_DEV_ALLOWED_ORIGINS 为逗号分隔主机列表；生产构建忽略此设置（frontend/AGENTS.md:224-227）。

    Q8：uv lock --check 失败 / CI 报版本漂移？ 改过 backend/pyproject.toml 或 harness pyproject 但没刷新 backend/uv.lock。补跑 uv lock；若是发版，直接用 scripts/bump_version.sh <ver>（它会顺带刷新锁并自检，bump_version.sh:108-113）。pre-commit 的 uv-lock-check 钩子本来能本地拦住，别用 --no-verify 绕过（.pre-commit-config.yaml:17-22）。

    Q9：Docker 里 extensions_config.json 写不进 / 更新丢失？ 生产 Compose 故意以读写挂载该文件（config.yaml 只读）；Gateway 写它时持双锁（进程锁 + sidecar advisory 文件锁）并临时文件原子替换。挂载点 EBUSY 才允许非原子原地覆盖（可能因崩溃截断）——出现这种情况要检查挂载方式（backend/AGENTS.md:22）。

    Q10：跑 make test-shard 报 .test_durations 缺失？ 分片基线文件不在就拒绝运行（防并发写竞争）。执行 make test-shard-durations 重建并提交（backend/Makefile:50-58）。日常全量测试直接 make test。

    Q11：live 测试意外调用了真实 API？ DEER_FLOW_RUN_LIVE_TESTS=1 是全局开关，跑完记得取消；离线分片本身带 -m "not live" 排除（backend/Makefile:52）。同理，基准评测命令永不静默下载数据集，数据集路径由你提供（第 19 章 19.4）。

    Q12：上传 Excel/Word 后 agent 读不到内容？ 文档转换走 markitdown、每请求单转换 worker；目录会被拒绝（上传全有或全无），同请求重名文件自动加 _N 后缀（backend/AGENTS.md:286）。先看 Gateway 日志里该上传请求的转换错误，再确认文件类型在支持列表内。

    Q13：定时任务的队列里的 run 一直不动？ 查三个预算：全局 max_concurrent_runs: 3、每属主 max_concurrent_runs_per_user: 2、排队上限 queue_timeout_seconds: 3600（超时的发生被跳过且不发通知，config.example.yaml:2859-2867）。多实例下这些是跨 Pod 共享预算；单实例则是本进程预算。
